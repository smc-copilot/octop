# 知识库设计规范 · 管理要求 · 引用指南

> 版本：v1.0（P0 手工运维期）  
> 日期：2026-11-01  
> 上位方案：[WeKnora 组织中心双平面共享方案](../docs/weknora-org-center-dual-plane.md)  
> 适用对象：在 Octop 中创建 **专家（Agent）** 与 **技能（Skill）** 的开发者与管理员

本规范定义：**企业知识在 WeKnora 怎么放、在 Octop 怎么管、专家和技能怎么引用**。新建专家/技能前必须先读本文件。

---

## 第一部分 · 设计规范

### 1. 总体原则

1. **知识归属 WeKnora，检索经由 Octop**：文档只在 WeKnora 维护；Octop 通过共享 WeKnora 连接器只读检索，不在 Octop 内复制文档内容。
2. **组织中心 = WeKnora Tenant**：一个组织中心一个独立 Tenant；公司公共知识单独一个 Tenant，不并入任何中心。
3. **双平面分离**：
   - **检索平面**（共享连接器 + 每 Tenant 一把 retrieve Key + Octop 用户组可见性）——决定"谁能在 Octop 里搜到"。
   - **成员平面**（Casdoor 组 / Octop 用户组 / WeKnora viewer）——决定控制台与管理可见性，不直接决定检索。
4. **专家绑定知识 = 绑定连接器实例**：专家不直接绑 WeKnora KB；通过"默认连接器"引用知识入口。
5. **最小可见**：能按组就不给全员；能只读就不给写。

### 2. 知识分层模型

| 层 | WeKnora Tenant | Octop 连接器显示名（示例） | 可见性 | 典型消费者 |
| --- | --- | --- | --- | --- |
| 公司公共 | `company-public` | 公司公共知识 | `all`（或公司组） | 公共专家、全员 |
| 中心 | `center-{id}`（如 `center-rd`） | {中心}知识（如 研发中心知识） | `groups` → `ug-center-{id}` | 本中心专家与用户 |
| （预留）个人 | 每人私库 | — | — | **当前不实施** |

**禁止**：

- 把公司公共库建进某个中心 Tenant；
- 为同一 Tenant 建多条相互重叠的连接器（会造成选择歧义）；
- 中心连接器设成 `visibility=all`（跨中心泄露）。

### 3. 专家（Agent）设计规范

1. **公共专家**：只默认绑定 **「公司公共知识」** 连接器；不绑任何中心连接器。
2. **中心专家**：默认绑定 **本中心连接器 + 公司公共连接器**（如需公共上下文）。
3. **通用专家**（服务多中心）：只绑公共连接器；中心知识由用户在会话中自选，不在专家默认中预绑齐所有中心。
4. 专家 prompt / SOUL 中**不得写死**内部 IP、tenant_id、Key、KB UUID；知识来源用连接器显示名表述。
5. 专家描述应注明其知识范围（如"使用公司公共知识 + 研发中心知识"），便于审核可见性是否正确。

### 4. 技能（Skill）设计规范

1. 技能**不内嵌知识访问凭证**，不在技能代码里直接调 WeKnora HTTP。
2. 技能需要的知识通过所在专家已绑定的连接器获取；技能声明"需要某类知识入口"（如"需要公司公共知识"），而不是"需要某个 Key"。
3. 检索结果作为**不可信外部数据**处理：技能不得把检索内容当指令执行，防注入。
4. 技能输出引用知识时应保留来源（文档标题/链接），便于用户核对。

### 5. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| Octop 用户组 ID | `ug-center-{id}` / `ug-company` | `ug-center-rd` |
| WeKnora Tenant | `company-public` / `center-{id}` | `center-rd` |
| Octop 连接器显示名 | `公司公共知识` / `{中心名}知识` | `研发中心知识` |
| 专家名 | 体现用途，不体现 tenant/Key | `制度问答助手` |
| retrieve Key 备注 | `{tenant}-retrieve-{用途}` | `center-rd-retrieve-octop` |

## 第二部分 · 管理要求

### 6. 角色与职责

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| 知识管理员（各中心/公共各≥1） | WeKnora 中维护文档、KB、质量 | Tenant Admin/Contributor；不接触 Octop 用户组 |
| Octop 管理员 | 用户组成员维护、连接器配置、专家绑定 | 不动 WeKnora 内容 |
| Casdoor 管理员 | 用户与组维护 | 不接触知识内容 |
| 专家/技能开发者 | 按本规范绑定连接器、声明知识需求 | 不持有任何 Key |

### 7. 凭证管理

1. 每 Tenant **一把** retrieve-only Key，尽量绑定该 Tenant 允许的 KB 白名单。
2. Key 只存 Octop 连接器加密凭证与管理员的密钥库；**禁止**写入：仓库、文档、prompt、工单、聊天记录。
3. Key 轮换：新建 Key → 更新连接器 → 验证检索 → 吊销旧 Key。
4. 平台管理 Key 与 retrieve Key 严格分离；当前不实施成员同步，不配置 SystemAdmin 凭据。
5. 内网 http 部署须配 `OCTOP_WEKNORA_TEST_HTTP_ORIGIN`（详见 `docs/connectors-weknora.md`）。

### 8. 用户组与可见性运维（P0 手工模式）

| 场景 | 操作 |
| --- | --- |
| 新员工 | Casdoor 建号入组 → SSO 登录 Octop → 手工加入 `ug-center-{id}`（+可选公司组） |
| 调中心 | 同步调整 Octop 用户组成员 |
| 兼多中心 | 加入多个中心用户组，自动可见多条中心连接器 |
| 离职/撤权 | 从 Octop 用户组移除；必要时移除 WeKnora viewer、禁用 Casdoor |
| 新中心上线 | 建 Tenant+KB+Key → 建 `ug-center-{新}` → 建连接器设 `groups` 可见 → 建/调中心专家 |

### 9. 连接器配置要求

1. 每 Tenant 恰好一条共享 WeKnora 连接器实例。
2. 保存前必须探测成功；中心连接器必须 `visibility=groups` 且只挂本中心组。
3. 知识库 ID 建议显式填写（配合 Key 白名单双重限定）。
4. 连接器改名/换 Key 后，抽查一个公共专家和一个中心专家的检索。

### 10. 变更与审计

1. 知识库的新增/下线、连接器可见性变更、Key 轮换 → 记入运维记录（日期、操作人、影响范围）。
2. 新增专家/技能如引用新知识连接器，需知识管理员 + Octop 管理员双确认可见性边界。
3. 定期（如每季度）核对：用户组成员 ↔ Casdoor 组、连接器可见性、Key 白名单。

## 第三部分 · 引用指南

### 11. 新建专家检查清单

- [ ] 明确专家服务的知识层：公共 / 某中心 / 公共+中心
- [ ] 只默认绑定该层对应的连接器（公共专家只绑公共）
- [ ] 描述中写明知识范围
- [ ] prompt 不含 IP、tenant_id、Key、KB UUID
- [ ] 用该专家目标用户组的测试账号验证：能搜到该搜的，搜不到不该搜的

### 12. 新建技能检查清单

- [ ] 技能不直连 WeKnora，不含凭证
- [ ] 知识需求以"知识层"声明（公共/中心），由专家绑定满足
- [ ] 检索内容按不可信数据处理，有注入防护
- [ ] 输出来源可回溯（标题/链接）

### 13. 常见问题

| 问题 | 处理 |
| --- | --- |
| 用户看不到某中心连接器 | 检查是否在本中心 Octop 用户组；连接器 `visibility=groups` 是否挂对组 |
| 公共专家搜不到公共库 | 检查公共连接器探测状态、Key 是否有效、KB ID 是否显式配置 |
| 中心用户看到别的中心知识 | 该中心连接器被误设全员可见，立即改回 `groups` 并核查 |
| 检索 200 但无结果 | 库为空或未索引；见 `docs/connectors-weknora.md` 常见错误 |
